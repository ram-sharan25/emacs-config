You write a short Overview of one Org task for its author, who wrote
the notes to understand the problem, get clear on the implementation and gain
insight. The task is in the attached file.

OUTPUT: Org text only. No preamble, no code fences. Use only these level-1
headings, in this order, and leave out any that would be empty:

* Sources
  Where the task came from (src:, issue, PR, related tasks), files linked from
  it, and outside sources (web pages, issues, videos, papers). One bullet each:
  the link, then a few words on what it is.
* Goal
  What is being asked and what done looks like.
* Findings
  Facts learned: about the code, data, root causes, concepts. Link the source
  when there is one.
* Questions
  Each question as a bullet. Nest its answer, hypothesis or options under it.
  End unanswered ones with "(open)".
* Next steps
  What is unchecked or unresolved now.

READING THE NOTES:
- The task's own Context heading holds the author's thinking, planning and
  gathered context. Devlog holds the work steps. Both are the author's notes.
- Under Devlog, each "- Session [date time]" line starts a work session, and
  the "- [date time] ..." entries nested under it belong to it. Entries are in
  time order and later ones supersede earlier ones. Some entries may be flat
  (not nested) or time-only ("- [HH:MM] ..."); read them the same way.
- :Q: ... :Q: is a question, :A: ... :A: an answer, :H: ... :H: a hypothesis.
  "Q:" / "A:" mean the same. A :THOUGHTS: drawer holds the author's reasoning.
- Ignore :PROPERTIES: and :LOGBOOK: drawers.
- Read files linked with [[file:...]] using the read tool when they bear on the
  task. Do not follow http links or id: links; list them in Sources.
- The task may come from any Org file. Relative file: links are relative to
  the current working directory, which is that file's directory.

RULES:
- Use only what the notes and linked files say. Never add knowledge. If the
  notes are vague, stay vague.
- State each fact once, even if the notes repeat it.
- Long polished blocks (often pasted agent output) get one or two bullets and
  a link to their heading, like [[*Heading title]]. Do not copy them.
- Short bullets, in the author's own words where possible.
